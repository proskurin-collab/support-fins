# Support Fins

**Поставьте деталь на ребро, и Support Fins добавит отламываемые рёбра поддержки,
которые позволят напечатать её в этом положении — прямо в STL.**

Приложение доступно на **[printfins.com](https://printfins.com)**. Работает целиком в браузере:
без загрузки файлов на сервер, установки и регистрации.

## Зачем

Печать детали плашмя обычно даёт наименьшую прочность. В испытаниях горизонтальное или диагональное
расположение слоёв оказывается до ~3× прочнее вертикального. И всё же большинство печатает плашмя:
для прочной ориентации нужны поддержки, а поддержки слайсера оставляют следы на поверхности,
расходуют пластик и порой снимаются дольше, чем проектировалась сама деталь.

Встроенные рёбра решают эту проблему. У них есть преимущество, недоступное поддержкам слайсера:
поддержка находится в самом STL. Отправьте его куда угодно — на любой принтер, с любым пластиком,
в любой слайсер — и результат сохранится. Слайсер же выдаёт gcode только для одного принтера.

Ни один слайсер такие рёбра не создаёт. Весь список типов OrcaSlicer — Grid / Snug / Organic / Tree
Slim / Strong / Hybrid; ни один из них не меняет сетку и не соединяется с деталью намеренно.
Сам приём не нов: Slant3D годами рассказывает о встроенных поддержках. Но до сих пор
их каждый раз приходилось вручную моделировать в CAD.

## Как это работает

1. Импортируйте STL, 3MF или STEP.
2. Поверните деталь. Решаете вы: Support Fins предлагает, но не выбирает за вас.
3. Приложение сразу показывает число нависаний, сколько из них можно поддержать настоящим ребром,
   высоту и контакт с печатным столом. Укажите направление нагрузки и ответьте на один вопрос —
   *она растягивает деталь или изгибает её?* — чтобы оценить ориентации ещё и по прочности.
4. Экспортируйте. Рёбра и опорная площадка уже входят в STL (или 3MF).

**Почему поворот выбираете вы, а не программа:** слово «прочнее» ничего не значит без направления
нагрузки, а в геометрии оно не записано. Если дать решателю полную свободу, он предложит деталь
высотой 155 мм, балансирующую на игле с двумя рёбрами размером с паруса: формально оптимально,
но напечатать невозможно. (Наш именно так и сделал.) Поэтому человек принимает единственное
решение, которое недоступно программе, а программа берёт на себя остальное.

## Состояние проекта

Веб-приложение уже работает и поддерживает полный цикл: загрузку, поворот, оценку, добавление
рёбер и экспорт. Геометрический движок проверен на сторонних STL и закреплён автономными тестами.

Работают: поиск нависаний, проверка доступности со стороны печатного стола, отламываемые стенки
с контурным верхом, оценка ориентации и направления нагрузки, комбинированное ребро (стенка и
соединительные перемычки, вплавляющиеся в деталь — именно в них суть; см. `docs/FIN-SPEC.md`),
необязательные стабилизирующие распорки, удерживающие боковые поверхности высоких деталей по всей
высоте (автоматически или щелчком по вертикальной стороне в режиме «Ручное размещение»), импорт
STL, 3MF и STEP, экспорт STL и 3MF.

Ещё предстоит: масштабируемые профили рёбер и опорная площадка при экспорте наклонённых деталей.

### Стабилизирующие распорки для высоких деталей

У высоких тонких деталей есть проблема, для которой обычные рёбра не предназначались: нависаний
нет, но по мере печати трение сопла и усадка каждого остывающего слоя смещают верх детали.
Она уходит в сторону, прогибается или качается, и каждое движение проявляется в линиях слоёв.
Стабилизирующие распорки удерживают её вертикальные стороны жёсткой опорой по всей высоте.

**Что такое стабилизирующая распорка:** вертикальное ребро, стоящее **торцом** к вертикальной
стороне детали — в направлении своей наибольшей жёсткости. У печатного стола оно глубокое,
кверху сужается до плоской вершины шириной 4 мм, утолщается с увеличением высоты и стоит на тонкой
подошве. Горизонтальные соединительные перемычки высотой в один слой, расположенные **равномерно
по всей высоте**, связывают его с деталью. Как и остальные поддержки, оно отделено от детали
зазором для отламывания; касаются детали только перемычки.

**Как пользоваться:** включите **Стабилизирующие распорки (высокие детали)** на панели настроек.
По умолчанию они выключены.
- **Авто** укрепляет самые высокие стороны: до четырёх граней, обращённых в разные стороны,
  чтобы удерживать обе оси; каждое ребро ставится в самой высокой части своей грани.
- **Ручное размещение**: щёлкните по вертикальной стороне, чтобы поставить распорку.
  Щёлкните по добавленной поддержке, чтобы выделить её (янтарным), затем нажмите **Delete**
  или **Удалить выбранное**; отмена действия вернёт её на место.
- После включения появляются три настройки: **Начало захвата распорки** (высота начала перемычек;
  0 = по всей высоте), **Шаг перемычек распорки** (по умолчанию 6 мм) и **Глубина распорки**
  (% от высоты у печатного стола; по умолчанию 15%).
- Между распорками остаётся не менее 1 мм воздуха. Распорка, которая пересеклась бы с другой,
  например поперёк узкого канала, не создаётся; приложение объясняет причину, чтобы вместо
  отламываемых частей не получился сплошной брус.

**Почему такая форма, а не прежнее ребро-распорка:** прежнее ребро лежит плашмя вдоль грани,
поэтому легко гнётся именно тогда, когда деталь на него наклоняется. Его перемычки сгущаются
у основания и редеют кверху, почти не удерживая верх высокой детали, где и возникает раскачивание.
Все размеры и их обоснование приведены в `docs/FIN-SPEC.md` (раздел «Стабилизирующие распорки»);
код находится в `web/sway.js`, а его поведение закреплено в `tests/sway.test.js`.

**Состояние: проверено печатью.** Разработано на колпаке для столба высотой 249 мм: режим «Авто»
ставит 4 распорки (около 20 г поддержки), а вручную поставленные распорки следуют его скатам
до высоты 225 мм. Оба пробных отпечатка (2026-09-22) получились чистыми, поэтому значения
глубины, толщины и шага перемычек по умолчанию подтверждены печатью, а не оценены на глаз.

### Сообщение «нет настроек, только геометрия»

При открытии 3MF **Bambu Studio** («неверная конфигурация, загрузить только геометрию») и
**PrusaSlicer** («не содержит конфигурации PrusaSlicer. Загружена только геометрия») показывают
уведомление и импортируют только сетку. Это **ожидаемо и безвредно**: слайсеры показывают его
для любого 3MF, содержащего только геометрию, в том числе из Fusion 360, FreeCAD и даже для
эталонных файлов консорциума 3MF. Деталь импортируется в правильной ориентации и размере,
рёбра — как задумано. Просто выполните нарезку с выключенными поддержками.
(OrcaSlicer открывает файл без уведомления.)

Экспорт намеренно содержит **только геометрию без профиля слайсера**: встроенный профиль убрал бы
уведомление, но при загрузке заменил бы настройки принтера, пластика и печати пользователя нашими.
Его пришлось бы заново готовить для каждого слайсера *и* каждой его версии. Это хуже однократного
безобидного уведомления для файла с уже правильной геометрией. Код записи — в `web/threemf.js`.

## Локальный запуск

Веб-приложение использует обычные ES-модули, сборка не нужна. Запустите прилагаемый сервер
разработки: он отключает кеширование, чтобы изменения действительно появлялись после перезагрузки.

```bash
python3 dev-server.py                      # http://localhost:8731/
python3 dev-server.py 8080                 # custom port
python3 dev-server.py --host 0.0.0.0       # reach from other devices on the LAN
```

По умолчанию сервер привязывается к `127.0.0.1` (доступ только с этого компьютера).
Передайте `--host 0.0.0.0`, чтобы открыть доступ из локальной сети. Это удобно для устройства
без монитора, например Raspberry Pi за межсетевым экраном; скрипт выведет адрес для подключения.
Порт задаётся необязательным позиционным аргументом; `--help` показывает все параметры.

Можно запустить тот же каталог `web/` в Docker: nginx доступен на порту 8731 хоста,
поэтому URL совпадает с адресом сервера разработки:

```bash
docker compose up --build        # http://localhost:8731/
```

Сборки и серверной части нет, поэтому образ — это просто `nginx:stable-alpine`,
раздающий статические файлы с такими же заголовками кеширования, как сервер разработки.
См. [`docker-compose.yml`](docker-compose.yml), [`Dockerfile`](Dockerfile) и
[`nginx.conf`](nginx.conf).

Прототип на Python — это проверка концепции, из которой перенесён движок: обычная математика
полигональных сеток без CAD-ядра.

```bash
pip install trimesh numpy manifold3d
python3 prototype/spike_overhangs.py yourpart.stl      # what needs support
python3 prototype/spike_fins.py yourpart.stl out.stl   # add fins
python3 prototype/spike_orient.py yourpart.stl         # rank orientations
python3 prototype/spike_arrow.py yourpart.stl 0,0,-1   # load-direction scoring
```

Тесты (Deno для JS-движка):

```bash
deno test --allow-read tests/
```

## Ограничения

- Нависания над самой *деталью*, а не над печатным столом, не поддерживаются: рёбра крепятся
  только к столу.
- При высоте стенки меньше примерно 4 мм места для полноценного ребра недостаточно.
- Программа намеренно не выбирает ориентацию за вас.

## Структура проекта

```
web/         the browser app (live at printfins.com)
plugins/     slicer/CAD integrations (PrusaSlicer, OrcaSlicer, Onshape)
prototype/   Python/trimesh proof of concept the engine was ported from
docs/        FIN-SPEC.md — the verified fin geometry, with sources
tests/       offline geometry regression suite
```

Рёбра добавляются к сетке отдельными замкнутыми телами; слайсер объединяет их. Весь движок —
обычная математика полигональных сеток без ядра булевых операций, чтобы он мог работать в браузере.
